**当前状态（2026-09-28）**：93 处光环标记（第 4 节按 90 行条目清单记录；天神断海经决策 46 移出专项）已完成盘点和分类；**AURA-01～12 全部实施完成，M3 已定稿验收通过**。socketlib 双客户端委托、AURA-07 视觉美术、火浣/罗汉（含小成档自动化与监听改名）、碧焰扣费前消耗与断海禁足必中均经用户实机验证通过；狂沙·孤影经决策 48 由监听自动化改为手动（两档防御 AE 留在物品上由玩家拖放开关）。框架与实机验收无遗留待验项；data/ 源 JSON 光环自动化数据复核按总计划 S5.9 分三批进行，批次结论回写本文件第 4 节。第 2 节为实施前背景，第 4 节记录条目边界，第 7 节记录进度。

## 1. 盘点口径

- 盘点范围：`data/**/*.json` 源数据。数据作者在需要光环自动化效果的条目上打了标记键 `"x-xjzl-aura": true`，盘点以该标记为准（解析 JSON 后按对象键定位，非文本检索；初始盘点的 94 处均为结构性标记，脚本字符串中无该标记）。
- 标记位置约定：neigong（19）、armor（1）、weapons（6）打在条目 `system` 上；wuxue 打在 `system.moves[]` 的招式对象上。盘点时共 44 个文件、94 处；2026-09-28 天神断海经决策 46 移出专项（标记删除），现余 44 个文件、93 处。
- 后续规则书新增光环内容时，沿用同一标记约定，并回填本文件对应分类表。

## 2. 实施前基础

- **payload AE 已按物品级 effects 承载**：光环的效果本体大多已录入为物品级 effects 条目（`transfer: false`，按等级/境界分档命名，如"无涯 (1级)/(2级)/(3级)"、"剑曲绝鸣 (敌方减益·领悟/掌握/精通)"），并已在 AE-10/AE-11 完成 V14 结构迁移与 `showIcon: 2` 常显。缺 payload 的条目多为依赖系统状态（目盲、禁足等）或纯规则效果。
- **实施前施加方式未使用区域**：手动拖拽 payload AE 给范围内单位、combatStart 等脚本一次性分发（马头琴、书香江南、惜余琴自身、青海），或由事件脚本提示手动结算。
- **旧可视化工具已停用**：`data/macros/utility.json` 的"⭕ [快捷] 创建跟随光环"宏基于 MeasuredTemplate（S1.14 已停用），其改写归 S4.3，并入本专项。
- **脚本式光环先例**：水中战斗（青海）AE 以 `flags.xjzl-system.radius` 存半径、`turnEnd` 脚本做维持消耗与广播——证明"AE 自带脚本 + 区域参数"路线可行，但无法覆盖进出结算与可视化。
- **S0.4 机制结论（光环实现的地基）**：Region 行为 `applyActiveEffect` 可对进出 Token 施加/移除特效；**区域进出/回合事件的派发口径（AURA-01 复测修正，见第 6 节决策 39）**：官方移动与 `document.update` 裸传送均派发进出事件，`updateSource` 纯内存写则无钩子、无事件、包含性跟踪也不更新；**非链接 Token 的 `token.actor` 是合成 Actor**，光环施加/清理必须处理该分支；`RegionDocument.createTokenEmanation` 可生成跟随区域；`attachment.token` 提供原生跟随（AURA-01 实测：须传 token id，grid 形状随源整格平移，源删除自动删区并补发 exit）。

## 3. 实现框架（2026-09-26 与数据作者讨论定稿）

实现采用一个自定义 Region 行为类型 `xjzlAura`；原甲/乙分别对应可组合的进入与回合结算开关，原丙/丁/戊/己分别归入节流选项、监听 AE、脚本分发和仅标记形态。第 4 节保留原分类名用于对账。

现有标记分布：进入/回合结算 66 处；监听 AE 6 处；脚本编排 9 处；脚本分发 2 处；仅标记 6 处；手动 4 处（借机窗口 2 处、万毒心经 1 处、狂沙·孤影 1 处，决策 48）。

### 3.1 行为类型与结算开关

| 结算开关 | 事件 | 动作 | 选项 |
|---|---|---|---|
| 进入结算 | `tokenEnter` / `tokenExit` | 挂 payload AE / 直接伤害治疗 / 两者选配 | `throttlePerRound` 限制进入事件；`oncePerRound` 使进入与指定回合事件共用每轮一次额度 |
| 回合结算 | `tokenTurnStart` / `tokenTurnEnd` / `tokenRoundStart` / `tokenRoundEnd`（核心 Combat 文档在指定 GM 端派发，且派发顺序在 ActiveEffect registry 刷新之后） | 伤害 / 治疗 / 挂 AE / 维持消耗（资源不足即散，青海脚本先例） | 可与进入结算同开（如水牢：进入伤害 + 回合开始流失） |
| 仅标记 | 无结算 | 只渲染范围 | 原己类用；配创建时说明卡 |

行为参数还包括：半径（米，按 1-2-2-2 折算格子集合）、阵营过滤（友方/敌方/全体）、是否含自身、战斗内持续回合数（0=不按回合自动到期）、单实例标签、payload 引用（物品效果或系统状态）、显示名与颜色。视觉增强（圆形轮廓与内力涟漪）为全局层，随 AURA-07 统一提供，行为 schema 不含粒子字段。

生命周期：装备、运功或架招等来源激活时由管理器创建 Region；来源失效时删除 Region，并在删除前结清账目。`cleanupOnExit: true` 时按 Region、行为与 Token 记录可叠层 AE 的实际新增层数，退出仅释放本光环贡献；非叠层 AE 由覆盖它的光环共享清理归属，最后一个归属退出时才删除非预存 AE。`cleanupOnExit: false` 时不记录清理账目，效果留待手动处理。战斗时限、装备和架招等来源的销毁由管理器处理。

### 3.2 范围与判定口径（2026-09-26 两轮拍板）

- 区域形状一律用 `grid` 类型（GridShapeData）：`offsets` 格子集合的成员判定、渲染、附着平移三者天然一致——**生效范围 = 可见范围 = 我们按 1-2-2-2 算出的格子集合**；`circle`/`emanation` 是欧氏几何圆，只配当视觉，不做生效判定。
- **单位（定案，决策 20）**：规则描述中的"米"即"格"，无任何换算、不读 `scene.grid.distance`；半径 N 米 = N 格，N 为非负整数。光环圆心一律吸附**格心**（从源 token 所在格中心按 1-2-2-2 公式算出覆盖格集合，复用 measured-template.mjs 保留的遍历算法；核心 Region 可锚格子顶点，这是我们的差异点）。附着跟随由核心整格平移 offsets。
- **进出判定直接采用核心包含语义**（决策 15，审阅修订）：核心 `testInsideRegion` 对 1×1 token 只测中心点（源码 `#getUnconstrainedTestPoints`："If at most 1x1, test center point"），即我们的中心格口径；多格 token 为足迹多测试点（任一命中即在内），按用户拍板接受核心口径、**不自研中心格状态机**。进出事件由核心派发，行为不做二次判定。
- **形状生成器**以圆形为主（约 99% 条目），支持矩形（3×1、3×3 等）与创建时按源 token 朝向的 90° 吸附旋转作为变体（剑气白云、刀气旋风）；多边形（星罗棋布棋子锚点）不支持，维持仅标记/手动。万剑归宗为**单 region + 大 offsets 集合**（剑痕触发不逐格消耗、湮灭一次性全清），不做逐格实例；区域内格间移动不重触发 `tokenEnter`，经 `tokenMoveWithin` 按**每次移动**结算一次（决策 23）。
- 无网格场景：grid 形状为空，系统直接禁用光环创建。**无实例查询（`queryTokens`）与 Region 判定同口径**：1×1 测中心、多格测足迹任一点（决策 35）。

### 3.3 UI 与创建路径

光环行为使用 `XJZLAuraBehaviorConfig` 配置结算字段；Region 的形状、颜色、可见性和楼层沿用核心配置页。三条创建路径汇入光环管理器：

1. **数据驱动**（主力）：装备/运功/进战时机自动创建，参数来自物品 payload 与光环约定，无 UI；
2. **快建工具**：区域工具栏按钮 → 填写半径、持续回合、颜色和跟随选项 → 在画布放置；脚本也可调用 `game.xjzl.auraQuick.place(params)` 请求玩家选择位置；
3. **配置页细调**：Region 的形状和外观在核心 RegionConfig 编辑，光环结算字段在 Behaviors 中编辑。

### 3.4 特殊实现形态

| 形态 | 写法 | 覆盖条目 |
|---|---|---|
| 监听 AE | 进入结算给范围内单位（含敌方）挂不可见监听 AE（`showIcon: 0`、无 changes），其脚本借**被挂者自身已有触发器**（attack/damaged/dying/death/turnStart）反向驱动持有者效果；离开撤销 | 原丁类 6 条（死人经、火浣功、罗汉伏魔功、随风潜入夜、沙罗染血、贞观治世） |
| 脚本编排 | 现有触发器 + `token.regions` 反查 + 管理器实例 API（按标签查询/消耗/删除场上光环）：出招引爆、破招/格挡触发放置、碧火检定消耗、湮灭联动 | 9 条：原丙类脚本部分 8 条（暗刻、遁光×2、踏莲、碧火×3、热恼地狱）+ 五雷真诀（attack 触发 + 区域查询替换手搓距离，决策 26 样板） |
| 脚本分发 | 进战脚本按条目规则向友方分发 payload AE，不建区域 | 2 条：赤霄剑（装备者由被动效果承载，副本只给其他友方）、马头琴·乘风（所有友方） |
| 被动计数 | passive 脚本按战斗中其他 Token 的状态动态计算自身加成 | 1 条：浴㞎功（战斗中其他 Token 的恶臭计数，不创建区域） |

**横切需求**（不单独成类，逐条标注在清单中）：

- **分档联动**：半径或数值按招式等级/内功境界/消耗层数变化（浩渺气海 1/3/10 米、无涯三级、剑曲绝鸣三档、须弥按层数）。payload 已有按档位建多条 AE 的先例；动态数值有脚本先例（随风潜入夜动态改范围）。
- **单实例替换**："只能拥有一个 X，新的替换旧的"（箫音障、寒霜、无涯、灼日、魔气、旋风等）与计数上限（腐蛊雾霭 1+up、暗刻 4、天候互斥）。区域需要 slug 化的实例管理，对齐 AE 的 slug/叠层语义。
- **维持消耗**：回合末扣内力，不足则消散（青海 10、江南 1、冷心按人数×20）。脚本先例完整（青海 turnEnd 维持）。
- **生命周期绑定**：装备/运功/架招开启 → 创建；卸下/解除/被破除/死亡/脱战 → 销毁并清理已施加 AE。语义对齐 `tiedToStance` 的业务清理。
- **时限到期**：区域持续 N 回合后自动消失，对齐 V14 `duration` 模型与核心 registry（AE-05 已确立 `expiryAction: "delete"`）。
- **过滤条件**：阵营（友/敌/全体）、是否含自身（"其他友方"不含自身）、濒死、架招状态、黑子/白子等自定义条件。

## 6. 决策记录（2026-09-26，与数据作者讨论定稿）

1. **Q4 架构方向定稿：完整光环系统（方案 B）**——自定义行为类型 + 光环管理器；核心 `applyActiveEffect` 行为（方案 A）否决：它走裸 `createEmbeddedDocuments` 不经过门面，丢 slug/叠层/权限代理/飘字语义。
2. **一个行为类型承载全部结算**：进入结算、回合结算与仅标记可组合；进入事件可挂 payload AE 或直接伤害治疗；`throttlePerRound` 限制进入事件，`oncePerRound` 联合限制进入与回合事件。
3. **范围判定**：grid 形状（GridShapeData）+ 1-2-2-2 offsets；1×1 Token 测中心，多格 Token 测足迹任一点；无网格场景禁用。
4. **UI**：行为结算字段使用 `XJZLAuraBehaviorConfig`，Region 外观沿用核心配置页；创建路径包括数据驱动、快建工具和配置页细调，脚本可调用快建放置 API。
5. **事件执行统一 GM**：进出事件虽在移动发起者客户端派发，行为 handler 一律经 socketlib 委托活动 GM 结算（当前端即 GM 时直接执行，避免无谓往返）——用户拍板"统一执行"。
6. **战斗外不结算**（用户拍板）：回合事件只在战斗内派发，战斗外光环仅保持区域存在与进出挂摘；乙类条目战斗外沿用手动。
7. **粒子为视觉增强层**（决策 47 更新）：AURA-07 已实施——圆形光环叠加圆形轮廓（不可关闭、无逐帧成本），粒子流转由客户端设置 `auraParticles` 即时开关（默认开）；不影响任何结算。
8. **原丁类定为监听 AE 形态，零新增脚本触发器**：7 条用现有触发器（death/dying/attack/damaged/turnStart）；随风潜入夜的"残疾检定"映射为濒死触发（dying）——数据作者确认残疾检定由濒死触发，不新增触发点（用户决策 2026-09-26）；借机窗口 2 条（罗汉棍阵、飞升）保持手动（用户拍板）。
9. **原己类定为仅标记形态**：只画范围 + 创建时一次说明卡 + 区域显示名；回合提醒默认关闭；G1 地形成本为 `modifyMovementCost` 实测通过后的可选后门，不进本轮承诺。
10. **原戊类除名**：赤霄剑按脚本分发实现，不占光环框架。
11. **S4.3 并入**：跟随光环宏的 Region 版改写与快建工具是同一件事，不另设入口。
12. **万毒心经手动结算**：毒血效果依所储毒药变化，由玩家与 GM 记录并处理，不创建自动结算区域。
13. **进计划验收矩阵的待实测清单**：

**第八轮修订决策（2026-09-26，第七轮审阅后确认，37～38）**：

**机制修正决策（2026-09-26，AURA-01 spike 实测，39）**：

**组合与条件语义（2026-09-27，决策 40～42）**：

40. **组合表达由多个行为承载**：单个 `xjzlAura` 行为只有一个 payload 槽位和一个回合动作；进入挂载与回合挂载需要不同 payload、或同一时机需要直接动作和挂载并存时，在同一 Region 添加多个行为。账目、过滤、时机和节流均按 `behaviorId` 独立。核心配置页的多行为组合仍列入 AURA-08 实机验证。
41. ~~回合挂载按 payload 叠层性分支~~：已由决策 45 取代。当前每个有效回合事件都调用一次 `addEffect`：可叠层 AE 累加，非叠层 AE 覆盖或刷新；同一行为的同回合重复事件由 `behaviorId|regionUuid|tokenUuid|timing|combatId|round` 去重。
42. **目标态条件挂载不做，条件类需求使用导体 AE**：Region 行为只负责按事件挂载 payload，不随区域内目标状态变化重新判断。需要动态条件时，由 payload AE 的触发脚本读取当前状态、挂载真实效果并管理清理；不在 Region 配置中新增脚本入口。

**账本身份（2026-09-27，决策 43）**：

43. **账本按行为分键**：结构为 `tokenId → behaviorId → entry`，条目保存 payload 引用快照 `ref` 与实际 `slug`；配置引用变化时，已有清理周期继续使用旧引用直至退出。同一 Actor 的 AE 操作按 `actorUuid` 串行。同名异 slug、同 payload 多行为和关联 Token 均通过行为键与账目归属区分。决策 45 保留该身份模型和引用冻结语义，并将条目字段收敛为清理收据。

**已取代的覆盖转移方案（2026-09-27，决策 44）**：

**当前业务模型（2026-09-27，决策 45）**：

45. **光环施加、记账与清理分离**：
   - **施加**：每个被接受的 `tokenEnter` 和有效回合挂载事件都调用一次 `addEffect`；叠层、覆盖与刷新由 AE 门面处理。`throttlePerRound` 是进入结算的唯一业务节流，`moveWithin` 只执行进入动作。
   - **清理账目**：Region flag 使用 `tokenId → behaviorId`，条目为 `{eid, actorUuid, tokenUuid, behaviorId, slug, ref, stackable, contributedStacks, existedBeforeAura}`。可叠层 AE 按贡献层数释放；不可叠层 AE 按 `actorUuid+slug` 汇总清理归属，最后一条归属结束且 `existedBeforeAura=false` 时删除。
   - **清理开关**：`cleanupOnExit=true` 时建立账目；`false` 时正常施加但不记账，退出、停用和删除 Region 均不清理。已有账目期间，开关和 `ref` 保持到退出；未记账的效果不追溯清理。
   - **执行与删除**：同一 Actor 的操作按 `actorUuid` 串行。`eid` 只在释放成功后登记。删除 Region 前必须等待账目预清理；失败时保留 Region 并允许重试。记账失败时回滚本次施加并继续抛出原错误，回滚失败时抛 `AggregateError`。

### 7.1 目标与边界

**目标**：以 V14 Region 体系重建光环/AOE 能力。实施前盘点 94 处标记；天神断海移出后现有 93 处，其中自动化候选 83 处（进入/回合结算 66、监听 AE 6、脚本编排 9、脚本分发 2）、仅标记 6 处、手动 4 处（借机窗口 2、万毒心经 1、狂沙·孤影 1）。第 4 节记录逐项边界。

**统一原则**（实现与数据录入的共同准绳）：

1. **区域行为只回答"谁在范围内、何时进出、何时回合结算"**；效果逻辑尽量落在 payload AE（`system.changes` + 既有触发器脚本）。复杂动态规则（随机表、检定、按计数结算）以监听模式录在 payload AE 脚本上——**本轮零新增脚本引擎触发器**（第 6 节决策 8）。
2. **目标侧结算归行为**（enter/exit 对称结算 + 区域内回合事件）；**源侧生命周期归管理器**（时限递减、维持消耗、脱战清理、孤儿校验）。所有结算统一落在活动 GM 端（第 6 节决策 5），避免双端竞态。
3. **生效范围 = 可见范围 = 1-2-2-2 offsets 格子集合**（grid 形状）；进出判定直接采用核心包含语义（1×1 即中心点，多格为足迹，见第 3.2 节）；`circle`/`emanation` 形状不用于生效判定。
4. **数据侧触发层**：物品/招式脚本在既有时机（combatStart/hit/damaged/attack 等，先例充分）调用光环管理器 API 创建/撤销；生命周期清理分三层——数据脚本时机（正常流）、系统级 Foundry 钩子兜底销毁（决策 16）、combatEnd 与 ready（战斗期清空与孤儿校验）。光环参数显式写在脚本调用里，不在物品 system 上新增光环 schema（未来若要声明式配置另立工作项）。战斗中换装不自动创建光环（决策 25 边界）。
